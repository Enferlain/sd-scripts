# Review: independent local operation/payload/resource extension (sd-scripts-syv.31.16)

## Verdict

**Approve.** The extension does what the milestone claims: an independently installed `pairing.pack`/`pairing.vector<width>` flows through the *unmodified* B session/preparation/runtime via three small common interfaces (`LocalTransform`, `TransparentLocal`, payload/resource ABI), every decoded local signature is cold-verified before any lowering factory runs, resources are pinned immutable snapshots, fusion is untouched and conservatively barriers on the new stage, and A/mixed explicitly reject accepted non-scalar local schemas before loading. I found no correspondence, authority, immutability, lifetime, or oracle-independence hole. Findings below are minor.

## What I verified

**Cold correspondence and ordering (the central claim).** In `prepare()` the only lowering-factory call site is `prepare.py:642-645`; everything precedes it: `check_plan` (envelope), `check_scalar_recipes` (whose whitelist now admits `LocalSignatureOp` only at recipe top level, `prepare.py:411`), `check_calls` over all decoded calls including fused leaves, exact signature coverage + per-signature **property equality** against the pre-dump resolutions (`prepare.py:594-599` — schemas compare structurally including `PairSchema` width, codec version strings, resource symbol/access/version/content-digest rows, outcomes), chain transport/property/role/order checks, and `local_groups` legality. `test_decoded_local_contract_corruption_precedes_lowering` pins zero factory invocations across all ten corruption cases (including the hand-fused pack+first group, correctly rejected by `groups()`'s eligibility re-check). The signature ops themselves are constructed in `resolve_local` during emission — construction is not factory invocation, so the claim holds exactly.

**Resource authority and immutability.** `resolve_local` (`payloads.py:96-158`) pins both directions: the op-declared `ResourceUse` (read from op properties by `PackContract.describe`) must match the installed `FrozenResource`'s `(version, sha256(values))`, access must be `read_frozen`, duplicate symbols rejected, resource-bearing stages require an installed `lower`, and declared resources must equal the binding's declaration. The factory receives only a `MappingProxyType` of the *declared* symbols (unrelated installed resource → `KeyError`, pinned); `FrozenResource` enforces a nonempty int tuple and is frozen (mutation pinned by `TypeError`/`FrozenInstanceError` tests). `needs_lowering` (the pack binding's raw `invoke`) is unreachable: `compile_local` builds stages from `lowered[origin]`, never `binding.invoke`.

**Runtime lifetimes and outcome semantics.** `ScalarFrame` (`runtime.py:101-158`): input-schema validation happens before the `entered` fact and before `_active_calls += 1`, so that failure path cannot unbalance the counter (and it is effectively unreachable downstream anyway, since stage N+1's input codec is by construction stage N's output codec — defensive only). Output validation runs strictly after `physical_end` (the `invoke_stage`/fused shell unchanged from `.31.12`); `LocalOutcomeError` is classified against the *semantic* contract's outcomes in `__exit__`, the `CallFact` is always appended and the counter always decremented, and an undeclared outcome additionally raises. The control reports confirm this clock-by-clock: `entered < physical_end < released < retired`, failed tickets stop at `pair.pack` with `publication_ack is None`, and dispatch counts reconcile exactly (3 unfused / 2 fused on failure; 24/18 = 6 tickets × 4/3 on the normal and hidden-lane runs).

**Oracle independence.** `wrong_hidden_lane_*` controls retain `pack.output = [1, 3]` with `status: "stopped"` and intact final-scalar arithmetic — i.e., `check_b` provably passes while `check_extension`'s independent coefficient expectation fails; the test pins this for both fuse modes. The projection adapter (filtering pack/first before `check_b`) is honest and its limitation is documented in the oracle itself.

**Fusion barriers.** `fusion.py` is unchanged (not in the changed-file set; eligibility still requires the exact record→record/no-resource/DEFAULT-outcomes contract). `pair.pack` is a barrier via `resources != ()`, `pair.first` via its unfamiliar *input* schema — no operation-name logic anywhere; `test_common_modules_do_not_import_or_dispatch_on_the_extension` greps the six common modules. Fused source groups are pinned as `((double, offset), (pack,), (first,))`.

**A/mixed/C regression safety.** `check_scalar_locals` is invoked at `model_adapter.py:375` and `mixed_adapter.py:337`, both before `lower_model`/`lower_mixed`/`backend.prepare`; both have direct regressions (`test_owner_target_rejects_accepted_non_scalar_local_schema_before_loading`, `test_mixed_runtime.py:297`). The widened `local_maps` is on the A/mixed *acceptance* path (`model_contract.py:70`, `mixed_contract.py:79`) but flattens identically for record chains, and `accept`'s endpoint checks were correctly moved ahead of local analysis (the recorded first failure, fixed at the right boundary). The grant/extension acceptance path returns before B-local analysis, so C is untouched. `may_effect` record maps still resolve via `invoke` with no snapshots; the removed dead `Prepared.maps` field has no remaining consumers.

**Evidence.** Qualification, 8 controls, normal fused/unfused reports and the pre_schema2 folder are internally consistent: manifest schema 2 matches the emitter field-for-field (including `read_frozen` digest row and `pair-int2-v1` codecs), report hashes are present, pre_schema2 is honestly labelled (no source hash, observations retained, report bytes identical to final — consistent with only manifest/guards changing), and `local_lowering`/`fused_groups` report actual formed groups (the `.31.12` follow-up lesson retained). Scope boundaries (no plugin discovery, no sandbox, trusted installed code, no perf/framework claims) are accurately stated in README and qualification.

## Minor findings (non-blocking)

1. **`payloads.py:105-106`** — `op.properties["source_id"]` raises a bare `KeyError` (not `NotReady`) for an installed `LocalTransform` op lacking that property, and the `assert isinstance(...)` disappears under `python -O` (later `source.data` → `AttributeError`). Trusted-install robustness only; use the explicit `implementation`/`local_effect` pattern.
2. **Reserved outcome labels are unguarded** — nothing prevents an extension declaring a failure outcome literally named `"returned"` or `"invalid_output"`. A `LocalOutcomeError("returned")` would be recorded as `outcome: "returned"` with `output: null` (the ticket still fails; the exception still propagates; oracles catch it), but the label collision with runtime-assigned meanings is a diagnostics ambiguity. A name blacklist in `local_maps`/`resolve_local` would close it.
3. **Diagnostics consistency** — the first two `resolve_local` messages (`payloads.py:102,104`) lack the origin prefix every other rejection carries.
4. **`FlowType.verify` (`dialects.py:36-38`) accepts any `TypeAttribute`, including `FlowType` itself** — purely structural; benign because readiness requires an installed codec, but the README's "installed payload type" wording describes the registry step, not this check. Optional clarification.
5. **Test-count arithmetic** — the recorded intermediate (442 full / 245 pure) does not trivially reconcile from `.31.15`'s 398/204 plus the 45 extension cases (one short); the 442→449 step reconciles exactly (+7: four nonlocal-ABI, snapshot-scope, no-dispatch, A owner-schema). Presumably a legacy case changed parametrization with the diagnostic reorder, but the qualification doesn't say which. Also `evidence_extension/qualification.json` still records `"review": {"status": "pending"}` — update at handoff, as in prior chunks.
6. **Base-B historical manifest** — the emitter is now schema 2 for *all* B preparations (the base fixture's manifest gains `local_contracts` for `data.double`/`data.offset`), so `evidence/bindings.json` (schema 1) no longer round-trips `__main__.py --manifest`. This is covered by the disclosed "historical manifests … rejected" statement in the extension section; a one-line note in the base B section would help readers.

## Conclusion

The incremental interface/schema/resource extension composes without any whole-session verifier, runtime case, or op-name dispatch; authority stays with the accepted interfaces plus the explicit installed registry, decoded signatures are pinned before lowering, immutability is mechanically enforced, physical/outcome/observer lifetimes are preserved and evidenced, and the hidden-lane control demonstrates genuine oracle independence. The findings above are robustness/diagnostics/hygiene items suitable for follow-up; none blocks this handoff.
