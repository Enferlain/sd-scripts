## Overall assessment

The implementation matches the stated intent, and the load-bearing invariants hold up under inspection. I found no correctness bug that breaks a stated requirement. Findings below are minor robustness/oracle-coverage items plus honest limits.

### Verified per scope item

1. **Ordered SSA availability** — `OrderedBody` (`contracts.py:101-129`) is applied via `RegionSemantics` (all structured ops) and `ProgramOp` (`dialects.py:226`). Diagnostics carry use/definition origins (op result index, sibling region/arg index); tests cover direct uses, nested/recipe captures, normalized shapes, self-use, and sibling-role borrowing (`test_structure.py`, `test_prepare.py:36-58`). `Analysis.value_sources` continues to handle initialized repeat carries, so recurrence is unaffected. Single-block region shapes make the "first block only" walk complete for this dialect.
2. **Binding authority before factories** — `prepare.py:302-347` checks capability *operand positions* (a payload schema named `capability` cannot impersonate authority — tested), traces each requirement operand through `value_sources` to its issuing access, verifies resource type/owner identity, kind, and mode (UPDATE ⇒ `owner_update`; reads ⇒ snapshot/protected/owner-update; GRANT never satisfies). I specifically checked the "empty issuers" hole: `value_sources` raises rather than returning empty, so the `for issuer in ...` loop cannot silently skip. Factories are constructed only in `Runtime.__init__` after its internal `load()` (`target.py:198`, states built at `target.py:252-279`), so all rejections precede initialization; the factory-counting tests confirm.
3. **One shared descriptor** — `BindingSpec.contract` (`prepare.py:67-89`) is the single source used by `_derive` (signature + effects) and by `local_rewrite.barrier`/`validate_groups`/`load`. Legacy absence stays unknown (`reads is None and not unknown_effects` ⇒ `ValueError`), and `data()` preserves legacy artifact spelling (`prepare.py:121-129`), so old prepared JSON still corresponds byte-wise while an effect-enriched manifest against an old artifact deliberately fails correspondence — a documented, conservative boundary.
4. **Zero-or-one filtering** — `lang.optional` + `ItemContract.forwards`, `CaptureShape` enforces exactly one claim in / bool out / optional out (`dialects.py:166-175`). Both executors deep-copy the payload for the predicate and return the pristine original plus upstream versions and `((stream,key),)` provenance (`reference.py:645-663`, `target.py:675-693`); `no_output` settles the output reservation while `filtered_out`/`forwarded` settle the input (`reference.py:680-687`, `target.py:736-744`). `verify.flow_links`' new forwarding fixpoint (`verify.py:700-722`) makes the kept flow's declared owners follow *actual* upstream dependencies (monotone, terminating; tested via `test_forwarded_versions_must_match_the_actual_upstream_owners`). Reservation-before-work is observable in the `prefetched` scenario (`capacity._value == 0` with 2 ready), and the new `_invoke`/`_body` disposal windows (`target.py:445-448`, `533-538`) cover cancellation between claim transfer and body entry (tested).
5. **Fusion** — real xDSL `PatternRewriteWalker` with SSA remapping; `FusedLocalOp` deliberately lacks `SymbolOpInterface` (cannot be a completion source), is rejected if authored (`prepare.py:234-235`), and is revalidated cold from the manifest (`load` → `validate_groups` + structure correspondence, `prepare.py:411-417`). The generated coroutine (`target.py:556-567`) calls each original stage through `_call`, preserving per-stage entry gates, validation, failure, and physical completion — verified by the dispatch-count and per-stage `physical_completed` equality tests, the `invalid_stage`/`cancel_local` "later stage not entered" assertions, and the opaque-barrier/forged-group negatives.

The engine is unchanged as scheduler; `filter_*` add bindings/scenarios only. Archive erasure (`erase`) clears facts/outcomes/traces/feed diagnostics while retaining settlements, requests, source receipts, and `controls.entered` — matching the spec table.

## Findings

1. **Low — dead code in `local_rewrite.barrier`**: after `not all(isinstance(v.type, PayloadType) ...)` returns a reason, the follow-up `if not isinstance(input_type, PayloadType) or not isinstance(output_type, PayloadType)` (second check) is unreachable. Harmless; trim or drop the duplicated branch.

2. **Low — reference/owner disposition divergence on failure interruption**: reference `FILTER` maps a sibling-failure `Cancelled` to `"cancelled"` (`reference.py:659-661`); target maps `CancelledError` with `self.cancelled == False` to `"discarded"` (`target.py:689-691`). Both settle exactly once, so conservation holds, but the two executors can label the same interruption differently, and no test compares disposition strings across executors in failure scenarios (`check_report` verifies key-set completeness only). If disposition names are meant to be part of the correspondence contract, unify or document; otherwise note it as a known oracle limitation.

3. **Low — `Runtime._dispose` silently tolerates double disposition** (`target.py:1130-1132`): it returns without error and, on a second call with a different disposition, would have overwritten `flow.settled[key]` if reached. The reference raises (`reference.py:732-734`). With history retained, `observe()` catches duplicates ("duplicate owner-visible fact key"), so interleaving comparisons are protected; under `erase_history` a hypothetical double-settlement would be silent. Consider at least asserting the disposition matches on re-entry.

4. **Low — oracle coverage gaps in `filter_checks`**: `check_settlement` skips the keys-1/3 drop receipts whenever `expected != EXPECTED`, and `cancel_local` never calls `check_settlement` at all — provenance/forwarding receipts are pinned only on success-shaped scenarios. Conservation and drain checks still cover the rest, but the strongest receipt checks don't run under interruption.

5. **Info — `OrderedBody` diagnostics for block args**: `parent.regions.index(value.owner.parent)` assumes the block is attached; fine for verified IR, and single-block region definitions make the walk complete. Graph execution is explicitly out of scope (documented in the trait docstring and README).

6. **Info — `data(Policy)`/`data(BindingSpec)` special cases**: correct for legacy equality; note the practical consequence that legacy artifacts cannot be re-qualified with effect-enriched manifests (deliberate, and stated in the README — worth keeping explicit in future migration notes).

7. **Info — `filter_qualification.child` env checks**: `authoring_blocked` asserts exactly the three non-`test_` modules; `test_*` blocking is covered only via the `authoring_loaded` sys.modules scan. Slightly asymmetric but sound. GIL observation is child-side only (before/after its imports, `PYTHON_GIL` must be unset) — matches "observed, not forced."

8. **Info — `filter_runtime.execute` timeout path**: on `wait_for` timeout the exception propagates before `conditions["run_raised"]` is set; the run fails loudly rather than misreporting. Acceptable.
