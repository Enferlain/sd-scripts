## Findings

**F1 — Low (latent robustness), `verify.py:722`.** In the new fixpoint, `dependencies_by_flow[source]` is an unguarded dict access, but `forwarded[flow]` holds `value_sources` results, which are documented/implemented to include `ResourceOp`s and ACCESS region ops — neither is a key of `dependencies_by_flow`. It is unreachable today because `ownership()` runs first in `verify()` and enforces `forwards ⊆ consumes`, consumed operands are `ClaimType`, and claims are only created by endpoint-typed `TakeOp`s that trace to flows. But a future claim-producing op (e.g., the "fork" the `repeated_claim` error text already anticipates) or a resource-derived claim would crash verification with a bare `KeyError` instead of a `SemanticError`. A `.get(source, …)` fallback with a defined semantic (or an explicit flow-only assertion raising a proper error) would close this.

**F2 — Info (consistency), `reference.py:691-693`.** The reference producer's exception path calls `_dispose` without the `ticket.disposition is None` guard the target now has. Currently unreachable in the reference's cooperative model (the reserved ticket is disposed only by the producer itself; the stopped-publish path disposes and returns normally rather than raising), so there is no behavioral bug — but under the new strict duplicate policy the asymmetry is fragile if the reference ever grows an interrupting publish.

**F3 — Info (scope boundary).** Interrupted *input* receipts (`"discarded"`/`"cancelled"`/`"failed"` on the raw side) are structurally validated only for the specific `invalid_stage` witness; the oracle's exhaustive per-item loop covers forwarded/filtered_out dispositions. This matches the stated claim ("every forwarded or dropped input"), but a corrupted cancelled-input receipt outside that scenario is not independently checked.

**F4 — Info.** `filter_runtime`'s `prefetched` scenario reads the private `flows["kept"].capacity._value`. Acceptable for a qualification harness, but it couples the oracle to CPython semaphore internals.
